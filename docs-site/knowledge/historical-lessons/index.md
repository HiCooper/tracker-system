# 历史踩坑记录

## ClickHouse 写入优化

**问题**: 单条 INSERT 写入性能差，高并发下连接数耗尽。

**解决**: 改为批量 INSERT（batch=100），配合 HikariCP 连接池。

**教训**: ClickHouse 推荐批量写入，单条写入约 10-20ms，批量写入可降至 2-3ms/条。

## Redis 去重窗口选择

**问题**: 去重窗口设置过长导致 Redis 内存占用过高，过短有漏去重风险。

**解决**: 5 分钟去重窗口 — 客户端上报重试间隔不超过 2 分钟，5 分钟覆盖正常重试。

**教训**: 去重窗口 = 最大重试延迟 × 2.5 倍余量。

## SPM 命名规范推广

**问题**: 初期埋点命名混乱，各团队随意命名导致数据分析困难。

**解决**: 制定 SPM 四级规范（a.b.c.d），工具化校验，CI 阶段强制检查。

**教训**: 命名规范需要在项目早期就强制执行，后期纠正成本极高。
