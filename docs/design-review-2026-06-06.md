## 三、关键缺失功能详解

### 🔴 P0 — 必须补齐（核心竞争力缺失）

#### 1. 漏斗分析 (Funnel Analysis)
所有主流埋点系统必备的分析模型。从"进入首页 → 浏览商品 → 加购 → 下单 → 支付"每一步都有流失，漏斗分析帮助定位转化瓶颈。

#### 2. 留存分析 (Retention Analysis)
评估用户粘性的核心指标，字节 DataFinder 将留存分析与用户分群深度绑定。支持自定义起始事件和回访事件，次日/7日/30日留存率矩阵表。

#### 3. 用户路径分析 (User Path Analysis)
腾讯 Beacon 的页面访问路径用桑基图展示用户跳转关系。阿里 SPM 体系天然支持路径追踪（spm-cnt / spm-url / spm-pre）。

### 🟡 P1 — 重要但可二期

#### 4. 埋点需求管理与审核流程
字节 DataFinder 的完整闭环：需求提交 → 方案设计 → 审核 → SDK 集成 → 实时验证 → 上线 → 血缘追踪。

#### 5. 埋点血缘 (Tracking Lineage)
展示事件/属性被哪些图表、分群、看板引用，评估修改影响范围。

#### 6. 埋点实时验证（Debug 模式）
实时查看埋点发送情况，支持按设备/用户过滤。

### 🟢 P2 — 增强差异化竞争力

#### 7. 用户分群 (User Segmentation)
基于行为特征和用户属性的动态分群，规则引擎驱动。

#### 8. 多维度下钻分析
按平台、渠道、版本、地域等 10+ 维度下钻。

#### 9. 异常监控与告警
核心指标异常波动检测，DLQ 堆积告警，钉钉/企微通知。

## 四、当前设计的其他改进建议

### 4.1 前端架构问题
- SpmApp/SpmPage 等类型缺少 version/status/owner/tags 字段
- TrendChart 组件仅支持固定双线，扩展性不足
- Store 层缺少请求去重和短时缓存

### 4.2 后端架构问题
- 聚合表缺少 page_code/channel/user_segment 等关键维度
- 只有 T+1 离线聚合，缺少实时聚合能力
- 看板系统是"死"的（静态 JSON），不是配置驱动的动态查询

## 六、总结

GateFlow Tracker 目前是一个**基础扎实但功能单一**的埋点管理工具。优势在于数据采集管线设计合理、SPM 四级层级模型借鉴了阿里 Aplus 的思路、前后端分离 + Mock 开发模式成熟。

但与腾讯 Beacon、阿里 QuickTracking、字节 DataFinder 相比，最核心的差距在于分析模型层面——缺少漏斗分析、留存分析和用户路径分析这三大分析引擎。建议优先实现三大分析模型，这是从"能用"到"好用"的分水岭。
